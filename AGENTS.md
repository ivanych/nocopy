# AGENTS.md — nocopy

## Что это

`nocopy.py` — CLI-утилита для копирования файлов из источника в целевой каталог
с пропуском файлов, которые уже существуют в целевом каталоге (определяется по
md5 с учётом всех вложенных подкаталогов). Реализована на Python 3, только
stdlib (argparse, hashlib, os, shutil, sys). Не требует сторонних зависимостей.

## Запуск

```
python3 nocopy.py [-e] [-c] [-s] <исходный_каталог> <целевой_каталог> [<промежуточный_каталог>]
```

Аргументы:
- `исходный_каталог` (обязательный) — откуда копировать.
- `целевой_каталог` (обязательный) — каталог, в котором ищутся дубликаты.
- `промежуточный_каталог` (необязательный) — если указан, файлы копируются в
  него, а не в целевой. Поиск дублей всё равно идёт по целевому каталогу.

Опции:
- `-e` / `--exec` — выполнить фактическое копирование. Без неё — только проверка
  и отчёт.
- `-c` / `--copy` — показывать в отчёте только файлы, которые будут скопированы.
- `-s` / `--skip` — показывать в отчёте только файлы, которые уже есть
  (не копируются).
- `-c` и `-s` независимы: вместе дают все файлы.
- Без `-c` и без `-s` таблица отчёта не выводится.
- `-i` / `--save-index` — использовать готовый индексный файл
  `.<target>.nocopy` из текущего каталога (файл не создаётся); если файла нет —
  выводится ошибка.
- `-I` / `--rebuild-index` — пересоздать файл индекса, даже если он уже
  существует. `-i` и `-I` взаимоисключающие.

## Логика работы

1. **Сканирование целевого каталога**: рекурсивный обход всех файлов
   (`os.walk`). Для каждого файла берётся размер, вычисляется md5 (чанками по
   8 КБ). Строится двухуровневый индекс `{размер: {md5: [пути]}}`. Показывается
   прогресс-бар.
2. **Поиск дублей в источнике**: файлы источника обрабатываются параллельно
   (пул потоков `ThreadPoolExecutor`, до `os.cpu_count()` и не более 32; каждый
   поток работает с общей потокобезопасной очередью `WorkQueue` и по мере
   освобождения забирает следующую необработанную задачу — динамическое
   перераспределение работы, «work-stealing»). Для
   каждого файла:
   - Сначала сверяется размер (быстрая отсечка, без чтения содержимого).
   - md5 вычисляется только если в целевом есть файлы такого же размера.
   - Если найден файл с тем же `(размер, md5)` в целевом — файл считается
     дубликатом (`SKIP`), не копируется.
   - Иначе — будет скопирован (`COPY`). Показывается прогресс-бар.

   Прогресс выводится **одним общим баром**: каждый поток заполняет свой сегмент
   бара (в TTY сегменты раскрашиваются разными цветами), части соединяются в
   единый бар, общий счётчик = количество файлов. Длина бара подстраивается так,
   чтобы строка бара целиком вписывалась в 80 колонок терминала. Ниже бара (только в TTY)
   для каждого воркера выводится строка
   `    #N [<обработано>] <суммарный размер> <скорость> <текущий файл>`
   (метка `#N` окрашена в цвет сегмента воркера; пока воркер работает, в качестве
   скорости показывается средняя скорость обработки воркером, в
   B/s/KB/s/MB/s/GB/s; после завершения воркера вместо неё выводится фраза
   `средняя скорость <скорость>` (средняя скорость обработки всех файлов этим
   воркером — суммарный размер обработанных воркером файлов, делённый на время
   его работы); имя обрабатываемого файла не выводится). Блок «бар + строки
   воркеров» перерисовывается
   целиком. Высота блока подстраивается под терминал: показывается столько строк
   воркеров, сколько помещается до нижнего края экрана (минимум — только бар),
   чтобы текст, выведенный до бара, не стирался из-за прокрутки. При редиректе
   вывода строки воркеров не показываются.
3. **Копирование** (при `-e`): файлы копируются в целевой (или промежуточный,
   если он задан) каталог с сохранением относительной структуры. Если по пути
   уже есть файл с другим содержимым — создаётся уникальное имя с суффиксом
   `_1`, `_2`, ... (например `file_1.txt`). Для копирования используется
   `shutil.copy2`. При конфликте имён в промежуточном каталоге существующий
   файл заменяется новым.

## Симлинки на каталоги

`iter_files` обходит символические ссылки на каталоги (в отличие от
`os.walk` с `followlinks=False`), и в целевом каталоге (построение индекса), и
в источнике (поиск дублей и копирование). Файлы внутри каталога-симлинка
получают относительный путь с префиксом имени симлинка (например
`~/alf/imm` → содержимое `~/immich`, путь `imm/photo.jpg`). Рекурсивные
симлинки (каталог, ссылающийся на себя) отбрасываются по `os.path.realpath`,
чтобы избежать зацикливания.

## Формат отчёта

Текстовая таблица с границами `+---+`. Колонки:
- `копирование` — метка `COPY` (будет скопирован) или `SKIP` (уже есть). `SKIP`
  выводится красным, `COPY` — зелёным (только в TTY).
- `исходный файл` — относительный путь в источнике.
- `размер` — размер исходного файла в человекочитаемом виде (B/KB/MB/GB/TB).
- `целевой файл` — для `SKIP`: путь к уже существующему файлу в целевом (все
  найденные копии выводятся списком); для копируемого файла без конфликта имён —
  наименование копируемого файла с отступом в 3 пробела (`   pic.jpg`).
  Если дублей в целевом несколько, в списке SKIP вместо отступа ставится
  ветвление: `┌╼` — первый файл, `├╼` — средние (второй… предпоследний),
  `└╼` — последний; при единственном дубле символ не ставится (только отступ
  в 3 пробела). При конфликте имён оба имени (оригинальное и новое с суффиксом
  `_1`, например `photo.jpg` / `photo_1.jpg`) выводятся с отступом в 3 пробела,
  перед вторым именем дополнительно ставятся символы `└╼ `
  (например `   photo.jpg` / `   └╼ photo_1.jpg`).
  Оба имени при конфликте выводятся ярко-жёлтым цветом (`\033[93m`, только
  в TTY). Промежуточный каталог не влияет на колонку «целевой файл»:
  конфликтные имена определяются по целевому каталогу.
- `промежуточный файл` — колонка добавляется только когда задан промежуточный
  каталог (последняя колонка): для `COPY` указывает путь в промежуточном, для
  `SKIP` — пустая. При конфликте имён в промежуточном каталоге существующий
  файл перезаписывается, а название файла в колонке выводится ярко-жёлтым
  цветом (`\033[93m`, только в TTY).

В конце — сводка:
```
Всего файлов в источнике : N (размер)
Будет скопировано (COPY) : N (размер)
Уже есть в целевом (SKIP): N (размер)
```
Строки «Будет скопировано (COPY)» (зелёная) и «Уже есть в целевом (SKIP)»
(красная) выводятся целиком цветными (только в TTY). В конце выводится
`Время работы: <всего> (индекс: <время>, поиск дублей: <время>)`.
При `-e` дополнительно: `Скопировано: N` и `Ошибок: N` (список ошибок).

## Ключевые функции (file:line)

- `file_size(path)` — размер файла (или None при ошибке).
- `human_size(num)` — размер в человекочитаемом виде.
- `md5_of_file(path)` — md5 файла по чанкам.
- `iter_files(root)` — рекурсивный обход: генератор `(абс.путь, относит.путь)`.
- `unique_target_path(target_root, rel)` — уникальный путь, избегает конфликтов
  имён суффиксом `_N`.
- `build_index(target_root, color=False)` — построение индекса
  `размер → md5 → [пути]` с единым прогресс-баром.
- `WorkQueue` — потокобезопасная общая очередь для динамического
  перераспределения работы (`next_item`).
- `ProgressBars` — единый прогресс-бар, сегменты которого заполняют потоки.
- `render_table(rows, headers)` — отрисовка таблицы с поддержкой многострочных
  ячеек и ANSI-кодов (ширина считается по видимым символам).
- `main()` — разбор аргументов, оркестрация, отчёт.

## Цвет и TTY

Цвет включается только когда вывод идёт в терминал
(`sys.stdout.isatty()`). При редиректе в файл/пайп ANSI-коды не выводятся.

## Известное поведение

- Дубликат определяется по `(размер, md5)`, независимо от имени файла.
- При нескольких одинаковых файлах в целевом — в отчёте показывается список
  всех таких путей.
- Порядок обхода файлов зависит от файловой системы (`os.walk` не сортирует).
